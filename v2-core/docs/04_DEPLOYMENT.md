# 04 — Deployment Guide (Backend)

---

## Arsitektur Deployment

```
v2-core/backend/
├── src/              ← TypeScript source (development)
├── dist/             ← Compiled JS (production — generated by tsc)
├── data/             ← Database SQLite + uploads
├── backups/          ← Database backups (via API)
├── logs/             ← Log files
├── .env              ← Environment variables (TIDAK di-commit)
├── .env.example      ← Template env (DI-commit)
├── .wwebjs_auth/     ← WhatsApp session storage
├── package.json
└── tsconfig.json
```

---

## Mode Development

### Backend (Express + TypeScript)

```bash
cd d:/CRM-AI/v2-core/backend
npm install           # Install dependencies (pertama kali)
npm run dev           # Jalankan dengan nodemon + ts-node (auto-reload)
```

- Menggunakan **ts-node** langsung — tidak perlu kompilasi
- Port default: **3002** (bisa diubah lewat `.env` `PORT`)
- Auto-reload via nodemon saat ada perubahan file `.ts`

### Frontend (React + Vite)

```bash
cd d:/CRM-AI/v2-core/frontend
npm install
npm run dev           # Vite dev server di port 5173
```

## Mode Production

### Build

```bash
cd d:/CRM-AI/v2-core/backend
npm run build         # tsc — compile TypeScript ke dist/
```

- Hasil kompilasi ada di `backend/dist/`
- Struktur di `dist/` mirror `src/`

### Start Production

```bash
cd d:/CRM-AI/v2-core/backend
npm run start:prod    # node dist/app.js
```

### Perbedaan Path (Dev vs Prod)

| Path | Dev (ts-node) | Prod (dist/) |
|------|--------------|--------------|
| DB file | src/config/ ke backend/data/ | dist/config/ ke backend/data/ |
| Uploads | src/ ke data/uploads | dist/ ke data/uploads |
| Config | src/config/ | dist/config/ |

Semua path menggunakan helper dari `backend/src/config/paths.ts` yang otomatis resolve dengan benar di kedua mode.

## Deployment Checklist

### 1. Persiapan
- [ ] `.env` sudah diisi (copas dari `.env.example`)
- [ ] `JWT_SECRET`, `SESSION_SECRET` diganti dengan string acak kuat
- [ ] `ADMIN_PASS` diganti (bukan default)
- [ ] `NODE_ENV=production`
- [ ] `CORS_ORIGINS` diisi domain frontend

### 2. Build
- [ ] `npm run build` — sukses tanpa error
- [ ] Folder `dist/` terisi

### 3. Test
- [ ] `npm run start:prod` — server jalan
- [ ] `curl http://localhost:3002/health` -> OK
- [ ] Login via API berhasil

### 4. Hardening
- [ ] Helmet CSP header aktif
- [ ] Rate limiter aktif di POST /api/chat/:storeId/send (30 req/min)
- [ ] Graceful shutdown: kill -SIGTERM clean exit
- [ ] WA client auto-restart jika disconnect

### 5. Monitoring
- [ ] Log files di backend/logs/
- [ ] Health endpoint di-monitoring (uptime, RAM, CPU, DB)

## Rollback Plan

```bash
# 1. Hentikan server
kill $(pgrep -f "node dist/app.js")

# 2. Kembalikan ke versi sebelumnya
git checkout <previous-tag-or-commit>
cd backend && npm install && npm run build && npm run start:prod

# 3. Atau restore backup database jika perlu
cp backend/backups/snapshot-*.sqlite backend/data/database.sqlite
```

---

## Risiko Operasional

1. **Database SQLite concurrent write**: SQLite hanya support 1 writer. Jangan jalankan 2 instance backend.
2. **Disk space**: Log dan backup bisa membesar. Monitor backend/logs/ dan backend/backups/.
3. **WA session corrupted**: Jika .wwebjs_auth/ corrupt, scan QR ulang.
4. **Port conflict**: Pastikan port 3002 tidak dipakai service lain.
